02

Problema

Mediante una entrevista y visualizacion del proceso de guardado de informacion, pudimos verificar los siguientes riesgos:

  • Riesgo de pérdida de datos por falta de respaldo adecuado.
  • Inconsistencias en la información debido a errores humanos.
  • Dificultad para acceder a datos históricos de pacientes y citas.

Estos problemas pueden llegar a afectar la eficiencia y calidad del servicio médico.

03

¿Cómo Funciona el Sistema?

El sistema tiene como objetivo principal optimizar los procesos clínicos mediante una herramienta tecnológica que reduce errores humanos y mejora el acceso a la información, tanto de pacientes, como secretarias, medicos y/o citas medicas.

🖥️

Interfaces Gráficas

Garantizan que el usuario final interactúe con una plataforma intuitiva y facil de usar.

🏗️

Organización Modular

Gracias a una arquitectura por capas, mantenemos el código perfectamente organizado, desacoplado y fácil de mantener o actualizar.

🛡️

Validación de Información

Garantiza la integridad de los datos antes de ser almacenados en la base de datos mediante controles:

  • Campos Obligatorios: Verificación de que no existan valores vacíos.
  • Validación de Documentos: Control de formato correcto.
  • Control de Fechas: En el módulo de Nueva Cita, la fecha debe ser seleccionada en el JCalendar.
  • Seguridad de Login: Comparación de credenciales con la base de datos.

Partes importantes

  • Uso de CRUD: El sistema permitió Insertar, actualizar, eliminar y listar Paciente, usuarios, citas y médicos.
  • Uso de clases DAO: Sirvió para separar el acceso a los datos, se aplico en PacienteDAO, UsuarioDAO, CitaDAO, etc.
  • Formularios internos: Usamos MDI (FrmPrincipal) y JInternalFrame para poder tener multiples ventanas interactivas.
